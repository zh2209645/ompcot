> Status review 2026-09-27 (omp 18.3.3 → 18.3.4 delta vs Ompcot v0.8.8 @ `495bef4`): no breaking change reaches the GUI's consumption surface. Live-probed rather than inferred — the embedded server boots inside `pi-coding-agent@18.3.4` (`bunx …@18.3.4 --mode rpc --extension extensions/dist/embedded-server.mjs`, scratch workspace) and answers every read-only WS command the frontend sends (`get_state`, `get_messages`, `get_omp_version`, `list_commands`, `get_available_models`, `list_auth_status`, `get_model_configuration`, `list_memory_files`, `list_agents`, `mcp.list`, `get_session_stats`; `mirror_sync_request` answers with the snapshot push, not a response frame — by design). `omp config list --json` returns an **identical 513-key catalog** on 18.3.2 and 18.3.4, and `omp usage --json`'s field set (incl. `reports[].resetCredits`/`metadata`) is unchanged, so no config/usage work is owed by this delta. Judged not-gaps: `task`'s `complexity` → `solutionSpace` rename (18.3.4 breaking; tool cards are value-keyed and carry no arg-name dependency — `tool-card.js` `getArgsPreview`), per-turn `auto` thinking (18.3.4; selectors already offer `auto` as a model-selector effort and `thinkingLevels` still reports `["off","minimal","low","medium","high"]` — live probe), live steering (18.3.3; the composer has shipped `deliverAs:"steer"` since A2 and `providers.openaiLiveSteering`/`steeringMode` land on the generic Other settings page), hidden session notices (dropped by both paths — live role gate `app.js:1263`/`1418`, history entry filter `session-resync.js:31-33` — so nothing leaks), `omp config set` failing loudly on a bare Windows profile (18.3.3; the write path already rejects on non-zero exit and shows a per-row error, so the change only removes a false "saved"), predictive text/SmolLM2 and the centralized download HUD (18.3.3; `TextPredictor` is host-native and no extension event/API exposes progress — terminal-only). Opened as gaps: **B11** (non-terminal `agent_end` treated as terminal), **B12** (displayable custom notices invisible), **B13** (tool-result `details`/`structuredContent` dropped), **B14** (`omp skill list` surface), **B15** (background-job panel over `ctx.getAsyncJobSnapshot()`), **B16** (`/btw`-style agent Q&A via `ctx.runEphemeralTurn()`).

> Runtime provider/model resync (post-v0.8.5): omp snapshots provider/model knowledge at process start — `models.yml` is parsed by `ModelRegistry`'s constructor and credentials are loaded into `AuthStorage` over the SQLite `agent.db` — so a provider, model, or key added while Ompcot ran (`omp login` / `omp config` in a terminal, another workspace window, a hand edit) stayed invisible to the model picker and the Providers page until the workspace restarted. `get_available_models` / `list_auth_status` now run `resyncModelSources()` first: `authStorage.credentials.poll()` (omp's external-commit probe) plus a `models.yml`/`auth.json` mtime+size gate around `ModelRegistry.refresh()`, so an unchanged list read costs a stat + two SQLite reads. The frontend matches that contract: the composer model dropdown re-fetches on every open, and the Providers page is a reload-on-open page (its models.yml editor skips the refetch while the textarea holds unsaved edits).

This document records which omp capabilities the GUI does **not** expose today, split by remediation cost, plus explicit non-gaps. Use it as the backlog source when planning GUI feature work.

## C. NOT gaps — agent-side capabilities already effective through the GUI

These run inside the agent; the GUI benefits automatically (tool cards render them normally). No GUI work required beyond ongoing rendering polish.

- `find` semantic workspace search (18.2.7) and `omp://` documentation search (18.2.9 / 18.3.0)
- Browser automation suite: a11y audit, React inspection, network/console, tracing, recording, downloads, WebMCP (18.2.8)
- Edit operations: `CUT`/`PASTE`, `Insert Before/After`, new edit-mode syntax (18.2.1 / 18.3.0)
- Background jobs & services: `wait`, `proc://`, `agent://` messaging (18.3.0, `wait` for agents 18.3.3) — the agent uses them; *surfacing* them is B15 and the run-state pause is B11
- Ephemeral `/btw` side turns for extensions (18.3.0; `/btw` in focused subagent views 18.3.3) — used by the agent; GUI parity is B16
- Judgment/batch evaluation (`judge`, `judge_batch`), TypeSafe provider (18.2.4 / 18.2.7)
- Image / speech / video pipelines (18.2.7 role-based models, 18.2.8 transcription)
- Auto-compaction with snapshot branches/rewinds (18.3.0)
- Secret obfuscation expansions (18.2.2)

## D. Out of scope — terminal-native, not recommended for GUI parity

- `omp stream` livestreaming, `/collab` relay hosts (18.2.5 / 18.1.20)
- `omp record` / `omp play` `.ompcast` (18.2.10)
- `omp bench` live rankings (18.2.10), `toks` offline token counting (18.3.0), `omp cleanse` (18.2.1)

## Recommended priority

1. **B5 slash commands** + **A1–A4 quick wins** — low cost, high visibility.
2. **B1 subagents** + **B2 MCP management** — omp 18.x's main evolution direction; largest experience gap.
3. **B3 OAuth login** — hard onboarding gap for providers without API keys.
4. B4 approvals, B6 usage, B7 fork — next tier.
5. B11 (non-terminal run state) — correctness fix for the 18.3.3 background-work pause; pair with B15 to show what the run is waiting on.
6. B12 + B13 — transcript parity for job notices and structured tool results (both are already on the wire).
7. B14, B16 — on demand.
8. B8–B10 — on demand.
